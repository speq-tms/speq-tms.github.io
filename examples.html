Examples

Start from the canonical SPEQ examples.

The speq-examples repository contains reference layouts for in-repository tests, dedicated test repositories, and the public JSONPlaceholder acceptance suite.

Repository layouts

In-repo mode

Keep SPEQ files under .speq inside the service repository. This is a good fit when API tests evolve with the service code.

Test-repo mode

Keep SPEQ files in a dedicated test repository. This is a good fit for black-box API testing across one or more deployed services.

JSONPlaceholder acceptance scenario

The canonical MVP acceptance suite lives in test-repo-mode-jsonplaceholder. It runs against JSONPlaceholder and demonstrates suites, modules, fixtures, generated data, retry policy, waiters, and report outputs. 

git clone https://github.com/speq-tms/speq-examples.git
cd speq-examples
speq validate --speq-root test-repo-mode-jsonplaceholder --format json
speq run --speq-root test-repo-mode-jsonplaceholder --env ci --tags smoke,api --report summary --output test-repo-mode-jsonplaceholder/reports/results/summary.json
speq report --speq-root test-repo-mode-jsonplaceholder --format allure --summary test-repo-mode-jsonplaceholder/reports/results/summary.json

Expected report paths

  • test-repo-mode-jsonplaceholder/reports/results/summary.json
  • test-repo-mode-jsonplaceholder/reports/allure
  • .speq-artifacts/logs when using the GitHub runner defaults.

Before local acceptance runs, remove old report output so you do not read stale results.

Version alignment

For MVP v1.0.0, keep these components aligned before release:

  • speq-cli: v1.0.0
  • speq-github-runner: v1 or exact v1.0.0 tag
  • homebrew-tap: formula version 1.0.0
  • speq-examples: commit or tag verified by acceptance gates
  • speq-vscode-extension: compatible with CLI v1.0.0
